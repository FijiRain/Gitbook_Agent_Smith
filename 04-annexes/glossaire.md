# Glossaire

Ce glossaire regroupe les acronymes et termes techniques essentiels rencontrés tout au long de cette documentation et du sujet **Agent Smith**.

---

* **ACI (*Agent-Computer Interface*)** : Interface Agent-Machine (par analogie avec l'IHM / HCI pour les humains). Désigne la manière dont les outils, leurs arguments et leurs formats de sortie (ex: numéros de lignes façon `cat -n`, messages d'erreur explicites) sont conçus spécifiquement pour maximiser les performances d'un LLM ([Yang et al., *SWE-agent*, 2024](https://arxiv.org/abs/2405.15793)).
* **API (*Application Programming Interface*)** : Interface logicielle qui permet de « connecter » un logiciel ou un service à un autre logiciel ou service afin d’échanger des données et des fonctionnalités de manière structurée.
* **AST (*Abstract Syntax Tree*)** : Arbre Syntaxique Abstrait. Représentation arborescente de la structure grammaticale d'un code source. En Python, le module standard `ast` permet d'inspecter et de valider le code généré par un LLM **avant** de l'exécuter dans la sandbox (pour bloquer des imports ou des accès mémoire interdits).
* **CodeAct (*Executable Code Actions*)** : Paradigme d'agent dans lequel le LLM génère directement du **code Python exécutable** en guise d'action (plutôt que des objets JSON d'appel d'outil), ce qui lui permet d'utiliser des variables persistantes, des boucles et des conditions ([Wang et al., 2024](https://arxiv.org/abs/2402.01030)). C'est le paradigme central d'*Agent Smith*.
* **JSON-RPC (*JSON Remote Procedure Call*)** : Protocole léger d'appel de procédure à distance utilisant le format JSON pour structurer les requêtes (`method`, `params`, `id`) et les réponses (`result`, `error`). C'est le format de message sous-jacent du protocole MCP.
* **LLM (*Large Language Model*)** : Grande famille de modèles de fondation entraînés sur de vastes corpus de données pour comprendre et générer du texte en langage naturel ainsi que du code informatique.
* **MBPP (*Mostly Basic Python Problems*)** : Benchmark créé par Google Research en 2021 ([Austin et al., 2021](https://arxiv.org/abs/2108.07732)) contenant ~974 problèmes algorithmiques courts en Python sous forme de fichiers JSON (énoncé + assertions de test). Il permet d'évaluer la capacité de synthèse de programmes d'un agent.
* **MCP (*Model Context Protocol*)** : Protocole ouvert introduit par Anthropic en novembre 2024 pour standardiser la manière dont une application d'IA (Host / Client) découvre et interagit avec des outils (`tools`), des sources de données (`resources`) et des modèles d'instructions (`prompts`) exposés par des serveurs externes. Voir le chapitre dédié [MCP : Le Model Context Protocol](../02-ecosysteme-technique/model-context-protocol.md).
* **Poka-Yoke (*Détrompeur*)** : Principe d'ingénierie industrielle (popularisé par Toyota, à l'image du port HDMI ou USB-C) consistant à concevoir un outil de telle sorte qu'il soit impossible de l'utiliser de travers. Appliqué aux outils d'un agent IA, cela consiste par exemple à exiger uniquement des chemins absolus (`filepath="/testbed/..."`) pour éviter toute erreur de répertoire courant.
* **ReAct (*Reasoning + Acting*)** : Architecture fondatrice d'agents autonomes ([Yao et al., 2022](https://arxiv.org/pdf/2210.03629)) qui fait alterner un raisonnement verbal explicite (*Thought*), une action dans l'environnement (*Action* / *Code*) et la lecture du retour réel de l'environnement (*Observation*).
* **SDK (*Software Development Kit*)** : Boîte à outils logicielle regroupant de la documentation, des bibliothèques de code déjà écrites et des utilitaires facilitant le développement pour une plateforme ou un protocole donné.
* **SWE-bench (*Software Engineering Benchmark*)** : Benchmark de référence composé de 2 294 problèmes réels (et 500 problèmes validés humainement dans sa variante **SWE-bench Verified**) extraits directement d'issues et de Pull Requests GitHub sur de grands dépôts Python open-source ([Jimenez et al., ICLR 2024](https://openreview.net/pdf?id=VTF8yNQM66)). Il évalue la capacité d'un agent à explorer un dépôt dans Docker et à produire un patch Git qui fait passer les tests.
